Plug the services you already use into your AI tools. Nothing leaves your laptop.

Pluk is a macOS menu bar app that turns Postgres, MySQL, SQLite, Linear, and more into local MCP endpoints. The server runs on localhost, each integration sits behind its own URL and policy, and every call an agent makes — allowed or blocked — lands in the activity log.

The problem

AI coding tools earn their keep exactly where your real things live — the production database, the issue tracker, the server you deploy to. The nervousness around granting access is rational.

Credentials you can't take back

A connection string pasted into a client config is a standing grant. You can't scope it to one agent, one task, or one afternoon.

Calls you can't see

Once access is granted, what the agent actually ran happens off-stage. You find out from the aftermath, not from a record.

No dial between read and write

Production wants "look, don't touch". A raw credential is all-or-nothing.

Pluk's answer is a broker on your own machine — local endpoints, a policy per integration, and a record of everything that ran.

How it works

A native menu bar app supervises a server on http://localhost:4242 that speaks MCP over streamable HTTP. Four steps from installed to agent-at-work:

  1. Add an integration

    Open Pluk from the menu bar and pick a type — the form shows exactly that adapter's fields. A Postgres or MySQL database with its optional SSH tunnel and SSL settings, a local SQLite file, a Linear workspace. Tunnels follow your ~/.ssh/config, Cloudflare Access included, and Test confirms the credentials reach the service.

  2. Copy its MCP URL

    Each integration gets its own endpoint, routed by a unique token: http://localhost:4242/mcp/<token>. One URL per service, so each agent sees only what you hand it.

  3. Paste it into your client

    Codex, opencode, Claude Code, Cursor, Windsurf, Antigravity — the detail view has a ready-made snippet for each.

  4. Let the agent work, inside the lines

    Tool calls arrive at the local server, the integration's policy checks each one, and every call — allowed or blocked — is written to the activity log as it happens.

What it connects to

Nine integration types ship today, each a self-contained adapter that brings its own config form, its policy treatment, and its tools. Adding another type is one module in pluk/src/adapters/ — the app picks it up with no other changes.

The nine integration types Pluk ships with, their policy, and their tool counts.
Service What it connects to Policy Tools
Postgres A network database — host, credentials, optional SSH tunnel and SSL SQL 12
MySQL A network database — same fields as Postgres, default port 3306 SQL 12
SQLite A local database file — no network, no tunnels SQL 12
Linear Your issue tracker — issues, projects, comments, notifications Action 14
Sentry Errors and structured logs — sentry.io or self-hosted Action 5
SSH A remote host — shell commands behind a strict allowlist Action + allowlist 2
Laravel Herd Feature sites per branch, served locally by Herd Action 3
Spark Mail Your mail, calendar, contacts, and meetings through Spark Desktop Action 22
GitHub CLI Your GitHub account through the locally installed gh Action 16

Read-only applies on top of either policy: SQL statements are classified one by one, action tools are gated individually as read or write, and SSH adds a command allowlist. Writes are blocked before they reach the service.

Bundle a group behind one URL

Most MCP clients connect to a fixed set of servers. A group hands an agent one URL covering a whole workflow — a database and Linear and an SSH host together — with every member's tools prefixed by its name so they never collide. Members keep their own policy and read-only flag: a read-only database stays read-only inside a group.

Local, logged, and in bounds

Local-first is the design, not a setting: Pluk itself runs entirely on your machine, and the policy engine decides what an agent may do before anything is sent.

The broker is local

The server binds to localhost. Your integrations, credentials, and logs live in ~/.pluk/, and secrets are never echoed back to the UI once saved. The services you connect to can be remote — Pluk brokers the connection from your machine; it doesn't pretend your database moved.

A policy per integration

Databases get a SQL policy engine that classifies every statement. API adapters get a read/write gate on each tool, and SSH adds a strict command allowlist. Turn on read-only and writes are refused before they reach the service.

Every call is logged

Allowed or blocked, each tool call lands in the local activity log — and the log updates live, so a new entry appears as the agent works, without a refresh.

One URL, one grant

The token in an MCP URL is a bearer secret: whoever holds it can use that integration. One URL per integration or group means each agent sees exactly what you intend — and nothing else.

Install

Pluk builds from source — no download to click, no account to make. You need macOS 14 or later, Bun, a Swift toolchain, and Make.

  • macOS 14 or later
  • Bun — curl -fsSL https://bun.sh/install | bash
  • A Swift toolchain — Xcode, or the Command Line Tools via xcode-select --install
  • Make — ships with the Command Line Tools

make install compiles the Bun server into a standalone binary, builds the Swift app in release mode, assembles Pluk.app, copies it to /Applications, and launches it. From then on, Pluk lives in your menu bar. To work on the app itself, make dev runs it from source.

Clone it, build it, and give your agent a single read-only integration first. The activity log shows you exactly what it does.
